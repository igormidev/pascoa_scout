## My Public Packages

Open source projects. In my Flutter developer career I built and published several open source packages. These are the strongest examples.

### `babel_text`

Package: [pub.dev/packages/babel_text](https://pub.dev/packages/babel_text)

A highly customizable rich text package for Flutter focused on dynamic text composition from a plain string.

With `BabelText` and its related widgets, you can:

- Map markers to text styles such as bold, italic, underline, and themed colors
- Attach callbacks to tappable text segments
- Inject inline widgets in the middle of the text flow
- Show hover tooltip messages for marked text
- Use selectable variants for copyable rich text
- Reuse app-wide default mappings for styles, widgets, and interactions

It is a practical abstraction over manual [`TextSpan`](https://api.flutter.dev/flutter/painting/TextSpan-class.html) trees when you need interactive, expressive text with much less boilerplate.

### `dart_debouncer`

Package: [pub.dev/packages/dart_debouncer](https://pub.dev/packages/dart_debouncer)

A package for building debounce flows in Dart with support for multiple independent debouncer instances.

- No singleton pattern required
- Useful for rapid user interactions such as button presses or text input changes
- Helps avoid unintended actions, unnecessary logic execution, and noisy updates

### `pricing_page`

## SaaS Attempts

Finished products. I tried to create several SaaS products in the past. I only finished and published two of them. These are real, dense products that ran in production and are now open sourced as curriculum projects.

### ZenScrap

- Website: [zenscrap.com](https://www.zenscrap.com/)
- GitHub: [github.com/igormidev/zenscrap](https://github.com/igormidev/zenscrap)

ZenScrap is an AI-assisted web scraping product that takes a target URL and a plain-language extraction request, then turns it into a tested scraper and reusable API.

Its core pitch was not just creating scrapers quickly, but keeping them alive by monitoring failures and repairing broken extraction rules automatically.

The workflow was intentionally simple:

- Paste a target URL
- Describe the data you want in natural language
- Let the platform generate a request contract and tested extraction logic
- Expose the result as a callable API endpoint
- Keep observing failures and auto-fix the scraper when the target site changes

Under the hood, it was a larger multi-service Dart system with:

- a Serverpod backend
- a Flutter client
- AI orchestration
- ScrapingBee execution
- analytics
- billing flows
- a self-healing loop as the main differentiator

### Mustache Hub

- Website: [mustachehub.com](https://mustachehub.com/)
- GitHub: [github.com/igormidev/mustachehub](https://github.com/igormidev/mustachehub)

Mustache Hub was a complete Flutter + Firebase product for creating, hosting, and filling structured Mustache templates with reusable variables, saved collections, shareable URLs, and generated final text.

It was designed for a pre-LLM workflow where you define the schema once, save the template online, and later fill a generated form to produce polished text on demand.

The product covered the full workflow:

- Define text, choice, boolean, and nested model variables
- Write Mustache-powered text sections against that schema
- Save templates online and organize them in a personal collection
- Reopen them later from the dashboard or by shareable URL
- Fill the generated form and get the final rendered output immediately

It also included:

- authentication
- collection management
- profile and account features
- responsive dashboard flows
- a custom editor-oriented architecture around template metadata and live generation

Archived product: Mustache Hub is no longer actively maintained and is kept online as a portfolio archive.
